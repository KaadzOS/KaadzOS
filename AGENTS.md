# KaadzOS Project Brief

KaadzOS is a Debian 13 (trixie) amd64 live and installable distribution built with live-build.

## Principles

- Keep the base ISO minimal: disable APT recommends, use short package lists, and provide heavy features only through on-demand packs.
- Use a polished, dark, high-contrast interface built around Sway and Wayland.
- Build and test entirely in GitHub Actions. Do not assume the development machine can build an ISO or run a VM.
- Use Cloudflare only for hosting: R2 for ISOs and the APT repository, and Pages for the website. Do not require servers.
- Do not use Hyprland because it is not in Debian stable.
- Verify every new package exists in trixie before adding it, using packages.debian.org, Debian's package API, or `apt-cache` in a trixie container.

## Operating Loop

For every implementation task:

1. Make the change and commit it.
2. Push the commit and trigger the relevant workflow. Pushes to `main` that touch build inputs trigger `build.yml` automatically (as well as the manual `workflow_dispatch` entry point); pushes that only touch `site/`, `docs/**` or Markdown skip the ISO matrix, while `v*` tags always run it in full.
3. Watch the run and inspect failures with the GitHub API or `gh run view --log-failed`.
4. Fix, commit, and repeat until CI is green.

Do not ask the user to paste logs. Do not begin a later phase until the current phase passes CI. Consult the live-build manual and actual build output when behavior is uncertain instead of guessing.

## Decisions

- Distribution and architecture: Debian trixie, amd64.
- Image format: hybrid ISO with Syslinux for BIOS and GRUB for UEFI.
- Installer: excluded from the Phase 1 image; installation support is planned for Phase 5.
- Package policy: `--apt-recommends false`; archive areas are `main contrib non-free-firmware`.
- Root filesystem: squashfs using zstd level 10 to favor CI build time while retaining useful compression.
- Base desktop packages: Linux kernel, Debian firmware, NetworkManager, Sway, Waybar, Foot, Xwayland, Fuzzel, and DejaVu fonts.
- Artifact naming: `KaadzOS-trixie-amd64.iso` with a sibling SHA-256 checksum file.
- Boot validation: QEMU tests both Syslinux BIOS and GRUB/OVMF UEFI boots, preferring KVM and falling back to TCG.
- Session readiness: CI requires a successful Sway IPC query, emits `KAADZOS_SWAY_READY` on the serial console, and captures a screenshot. It also fails the boot test if a `swaynag` process is present, since that means the Sway config emitted errors or warnings (for example an overwritten binding).
- Palette: the "AMOLED" palette in `theme/palette` is the single source of truth; `theme/generate.sh` renders the generated themed configs (Sway, Waybar, foot, fuzzel, mako, swaylock, GTK/Qt, wallpaper, console, Plymouth splash and Calamares branding) from it, while the boot-menu artwork and overrides are hand-authored from the same values. True `#000` background, white primary text and a white accent, with neutral near-black surfaces and near-neutral terminal slots; it matches the website's editorial black-and-white look rather than using a cyan/blue cast. Red is reserved for errors and urgent state. Calamares' third-party coloured surfaces are neutralized at build time because they are not palette-configurable: the locale map through an `LD_PRELOAD` QImage filter (alpha preserved for timezone hit-testing) and the hardcoded Breeze partition colours through a build hook that rewrites them to same-length greys and fails the build if Calamares ever changes them. Typography: the UI font is the website's Inter Tight — Debian's `fonts-inter` only ships Inter/InterDisplay, so the variable TTFs are vendored (OFL) into `config/includes.chroot/usr/share/fonts/truetype/kaadzos/` and `KAADZ_FONT_UI="Inter Tight"` is wired through every generated config; JetBrains Mono stays for terminals, DejaVu Sans is the fallback, and the Calamares QSS pins the font family because the installer runs as root without skel configs. All OS artwork is flat: the wallpaper, Calamares welcome/slide art, boot `splash.svg` and the Plymouth background are true black with hairline contour lines and waypoint dots only (no gradient washes or glows), and the generated GTK css flattens Adwaita's headerbar/button gradient overlays.
- Pack CLI: `kaadzos` is POSIX sh (dash-compatible) at `/usr/local/bin/kaadzos`, not Python or Go. The base image has no language runtime and apt-recommends is off, and the CLI only orchestrates apt/dpkg/curl, so a shell script adds no runtime payload or build toolchain.
- Pack format: the repo-root `packs/<name>.pack` files are canonical and declarative (`key=value`: `name`, `description`, `size`, `requires`, `apt`, `repo-url`, `repo-suite`, `repo-components`, `repo-key`, `hook`). CI stages them into `config/includes.chroot/usr/share/kaadzos/packs` before `lb build`; the staged copy is gitignored so the sources stay single-source.
- Pack manager behaviour: `add`/`remove` are idempotent and escalate with `sudo -E` only when needed; `list`/`status`/`addons` never require root; `update` refreshes indexes and upgrades. `KAADZOS_PACKS_DIR`, `KAADZOS_STATE_DIR`, `KAADZOS_DRY_RUN=1` (or leading `--dry-run`) support testing and alternate installs, with install state kept in `$KAADZOS_STATE_DIR/installed`.
- Third-party repos: packs may add a signed apt repo (android uses Waydroid's trixie repo and key) or fetch a static binary (cloudflare, architecture-matched). The CLI detects armored vs binary keys instead of assuming one format.
- Live sudo: the live user `kaadzos` gets NOPASSWD sudo from a build-time hook so pack installs work without a password in the live session; this is live-only and must be removed by the installer in Phase 5.
- Installer launch: the supported entry is `kaadzos-install` (Waybar **Install** button, `$mod+i`, or the "Install KaadzOS" fuzzel entry), which preserves the Wayland environment and pins `-c /etc/calamares`; the Debian `calamares.desktop` entry is hidden in the live image because its `pkexec calamares` path cannot work in this Sway session.
- CI installer driver: `kaadzos-ci-install` navigates Calamares with synthetic Sway pointer clicks (`seat - cursor set/press/release` on the bottom-right Next/Install button, resolution derived from the output mode) and types field values with `wtype`; `Alt+N` mnemonics are not used because focused combo boxes consume the key as type-ahead, and the CI Calamares process is pinned to `LANG=en_US.UTF-8`. The Summary page is held 8 s so `test-install.sh` can screenshot it before the install starts; the click coordinates and each page step are marked on the serial console.
- Add-ons UI: `$mod+a` runs `kaadzos addons`, a fuzzel menu that lists packs and installs/removes them in a terminal.
- Control centre: `kaadzos-control` is one POSIX-sh + zenity/fuzzel helper behind the Waybar gear, `$mod+Shift+s` and a desktop entry. Every optional command (`wpctl`, `nm-connection-editor`/`nmcli`, `brightnessctl`, `powerprofilesctl`, `wlsunset`, `upower`, Blueman) is probed, so a missing tool disables one item instead of breaking the menu; reboot and power off confirm through zenity. Base adds `upower`, `power-profiles-daemon`, `wlsunset` and `zenity`. The generated bar gains `backlight`, `power-profiles-daemon`, `idle_inhibitor` and `custom/control`; battery left-click opens the power section, and network left-click falls back from `nm-connection-editor` to the control centre.
- Portals and session integration: base ships `xdg-desktop-portal`, `xdg-desktop-portal-gtk` and `xdg-desktop-portal-wlr`; `/etc/xdg/xdg-desktop-portal/portals.conf` selects `gtk` by default and `wlr` for `ScreenCast`/`Screenshot`. The generated Sway config calls `dbus-update-activation-environment` for the private `dbus-run-session` bus and, with `--systemd`, the user manager, because both live and installed wrappers start Sway under `dbus-run-session`; `kaadzos-session-ready` activates `org.freedesktop.portal.Desktop` with a bounded `gdbus` Ping and emits `KAADZOS_PORTAL_OK`, which the live and installed gates require.
- Settings: `kaadzos-settings` is one POSIX-sh + zenity helper behind `$mod+comma` and the Settings desktop entry. It covers appearance (wallpaper, night light, dark/light style, interface font, icon theme), input (keyboard layout, touchpad tap), display, network, Bluetooth, sound, power, default browser/file manager and About; every optional tool is probed per row. Wallpaper, keyboard and touchpad overrides are written through `kaadzos-file-action` / atomic config.d files under `~/.config/sway/config.d/` (`*.conf` only, with an inert README and default file), preferences live in `~/.config/kaadzos/settings.conf`, and the generated Sway config ends with `include ~/.config/sway/config.d/*.conf`. `kaadzos-file-action` takes paths as arguments, rejects control characters, `$`, backticks and leading dashes, and never evals filenames. `kaadzos-session-ready` emits `KAADZOS_SETTINGS_OK`, which the live and installed gates require; `ci/test-file-actions.sh` and `ci/test-settings.sh` run in both container jobs.
- Files: Thunar keeps its native context menu and gains six safe actions from skel `uca.xml` (**Open Terminal Here**, **Copy Path**, **Set as Wallpaper**, **Open as Administrator**, **Install Local Package**, **Open Settings**), each calling `kaadzos-file-action`. Thunar expands `%f` with `xfce_g_string_append_quoted`, so field codes are left unquoted; the helper receives one argv, never evals, and refuses empty, leading-dash, control-character, `$` and backtick paths while validating the type per action. Archive create/extract is `thunar-archive-plugin` + `xarchiver` (xarchiver ships its own `/usr/lib/thunar-archive-plugin/xarchiver.tap`; the plugin package itself carries the ark, engrampa and file-roller taps), `wl-clipboard` backs Copy Path, and `gvfs`/`gvfs-fuse`/`udisks2`/`thunar-volman`/`tumbler`/`lxpolkit` add trash, removable media, thumbnails and the session polkit agent. Admin open uses Thunar's polkit-backed `admin://` location and needs the `admin` pack's `gvfs-backends` (log out and back in after installing it so gvfs picks up the backend); local `.deb` installs go through `kaadzos-packages install-deb` with a zenity confirmation and `pkexec` (or live passwordless sudo). `kaadzos-session-ready` emits `KAADZOS_FILE_ACTIONS_OK` and `KAADZOS_POLKIT_AGENT_OK`, which the live and installed gates require; `ci/test-file-actions.sh` and `ci/test-packages.sh` cover the paths in both container jobs.
- Greeter: the installed system keeps greetd + tuigreet. `kaadzos-install-finalize` pins VT 7 and adds the AMOLED white/grey `--theme`, the `KaadzOS` greeting and the Waybar clock format. tuigreet renders in the Linux VT font, so Inter Tight is not applicable; GTK greeters (`nwg-hello`, `gtkgreet`) need a compositor wrapper and are not adopted. `kaadzos-session-ready` emits `KAADZOS_GREETER_OK`, which `install-test` requires; `ci/test-greeter.sh` checks the theme, identity and Plymouth ordering in both container jobs.
- Search: `kaadzos-search` is one POSIX-sh helper behind `$mod+d`; `$mod+Shift+d` keeps the plain fuzzel launcher. It pipes one TAB-separated list (desktop entries, recent files from `$XDG_DATA_HOME/recently-used.xbel`, the 200 newest files from a depth-6 `timeout 2 find` over `$HOME`, settings pages, `kaadzos list` packs and a fixed command map) to `fuzzel --dmenu`, then dispatches `gio launch`, `xdg-open`, `kaadzos-settings <section>`, `kaadzos add <pack>` in foot, or a fixed command. It prunes `.ssh`, `.gnupg`, keyrings, browser profiles, trash, caches, `node_modules` and `.git`, drops control-character/newline names, refuses leading-dash values and never evals a filename. `ci/test-search.sh` covers spaces, Unicode, recent-file decoding, missing recent state, exclusions, every dispatch path, cancellation and the no-`eval` rule in both container jobs.
- Packages: `kaadzos-packages` is the base POSIX-sh + zenity front page behind `$mod+Shift+p`, the Waybar package module, the **Packages** desktop entry and the Settings row. It opens Synaptic when installed, offers the `admin` pack, refreshes apt with `pkexec` (or passwordless `sudo` in live), lists packs and explains the signed archive. Base adds `lxpolkit`, so the generated Sway config starts the session polkit agent; the `admin` pack supplies `synaptic`, `pkexec` and `gvfs-backends` (and keeps `lxpolkit` for older images). Install/remove validate the package name, pass it as one argv, confirm with remove defaulting to cancel, and distinguish a locked dpkg from an unreachable archive; `install-deb PATH` requires an absolute readable `.deb`, warns that maintainer scripts run as root, confirms with zenity, and keeps failed apt output in `~/.cache/kaadzos/apt.log`. `ci/test-packages.sh` stubs apt/pkexec/zenity/Synaptic/`kaadzos` in both container jobs; Synaptic itself is not launched in CI because the admin pack is optional.
- OpenCode: the optional `opencode` pack fetches a pinned v2.3.2 upstream archive over HTTPS, verifies its SHA-256 before extraction, and installs `/usr/local/bin/opencode` plus a desktop entry that is not part of the base image. No `latest` URL, install script, apt repo, key, credential, sudo rule, daemon or auto-start is added; amd64 and arm64 are the only supported architectures. `kaadzos-opencode` asks for per-directory zenity consent on first run, states the agent's file/command scope, records only the accepted path in `~/.config/kaadzos/opencode-consent`, validates and never evaluates the path, then opens the CLI in foot. Settings, Search and the desktop entry share that helper. `docs/opencode.md` records the digests, update policy and boundaries; `ci/test-opencode.sh` covers pins, fixture download/verify/install, gating, checksum failure, consent and a secret scan in both container jobs.
- Dock: no Wayland dock is adopted. `nwg-dock`, `nwg-panel`, `sfwbar` and the other Wayland docks are not in trixie; do not add an X11 dock or vendor a Go binary, and keep Waybar as the supported bar. Revisit only if a trixie package appears.
- Documentation and release readiness: `README.md` separates base, optional and hardware-dependent features and records the no-dock and licence decisions; `site/docs/` is a 27-chapter static manual whose search, scrollspy and copy buttons are progressive enhancements; `docs/release-notes/v0.4.0.md` is the prepared tag body. The opt-in pack matrix also includes `security` (`ufw`/`gufw`), `fonts` (Noto core/emoji/mono) and `input` (fcitx5 and frontends), with every package verified in trixie. No secret, non-free runtime dependency or new base daemon is added.
- Pack validation: the `pack-test` CI job runs `ci/test-packs.sh` in a trixie container to resolve every pack (apt names, repo fields, hooks) and exercise the CLI's dry-run, gating, idempotency and error paths without building an ISO.
- Helper validation: `ci/test-helpers.sh` runs `dash -n` and `shellcheck` over every shipped POSIX-sh helper, then the functional suites for search, file actions, control-centre absence paths, settings persistence, fake apt (pkexec and passwordless sudo) and the OpenCode dry-run/secret scan. Both container jobs install `shellcheck` from trixie. SC2024 is excluded because the sudo/Calamares and sudo/apt redirects are intentionally performed by the unprivileged shell; wrapping them in `sh -c` changed the installer launch environment and broke the Calamares window. `kaadzos-session-ready` emits `KAADZOS_LAUNCHER_OK` after checking helper binaries, desktop entries, launcher bindings and default MIME apps; the live and installed gates fail on `KAADZOS_LAUNCHER_MISSING` and require the OK marker.
- Boot splash: a script-based Plymouth theme (the `script` plugin ships in core `plymouth`; two-step/label plugins are not needed) is generated from the palette by `theme/generate.sh` into `/usr/share/plymouth/themes/kaadzos`; `/etc/plymouth/plymouthd.conf` pins `Theme=kaadzos`, a chroot hook runs `plymouth-set-default-theme` + `update-initramfs`, and a `kaadzos-quit-plymouth` unit ordered `Before=getty.target` (plus getty@tty1/greetd drop-ins and a defensive `plymouth quit` in the session wrapper) hands the display back before any session competes for DRM. The `splash` kernel argument is on both the live append and the installed `kernel_params`.
- Boot menus: no binary hooks — live-build (1:20250505+deb13u1) copies `config/bootloaders/{grub-pc,syslinux_common,isolinux}/` overrides after its templates, and one `config/bootloaders/splash.svg` is rendered by live-build into ISOLINUX 640×480 and GRUB 800×600 splash PNGs. GRUB waits 5 s, ISOLINUX 10 s, the installed system 1 s.
- Browser and defaults: `epiphany-browser` (GNOME Web) is the lean default browser — WebKitGTK renders natively on Wayland and it is the smallest full-featured browser in trixie; Thunar, Mousepad, imv and zathura+zathura-pdf-poppler are the lean file/text/image/PDF defaults, wired by skel `mimeapps.list` and `user-dirs.dirs` (`xdg-user-dirs` package). Screen recording is `kaadzos-record`, a wf-recorder toggle saving `~/Videos/KaadzOS-*.mp4`, bound to `$mod+Print`.
- Memory: `zram-tools` provides a zstd zram swap sized at 50% of RAM, paired with `vm.swappiness=180` and `vm.page-cluster=0` in `/etc/sysctl.d/40-kaadzos-mem.conf`; the boot test emits `KAADZOS_IDLE_RAM` (used/total/zram devices and size) to the serial log and the runner prints it per firmware.
- Bluetooth: `bluez` and `blueman` are base packages, with `dconf-gsettings-backend` and `libglib2.0-bin` explicit because apt recommends are off. `mako-notifier` already Provides `notification-daemon`, so Blueman does not add a second notification daemon. `config/hooks/live/0800-bluetooth.hook.chroot` enables `bluetooth.service`; Debian's unit carries `ConditionPathIsDirectory=/sys/class/bluetooth`, so a machine without an adapter skips the unit instead of failing it, and udev pulls `bluetooth.target` in when an adapter appears. Waybar 0.12's built-in `bluetooth` module maps its `off`, `on`, `connected` and `no-controller` states to Font Awesome icons, exposes the `discovering` CSS class while scanning, shows the connected device name (and battery percentage when BlueZ provides it), opens Blueman on left-click and runs `kaadzos-bluetooth toggle` on right-click; `$mod+x` opens Blueman. `kaadzos-session-ready` asserts `KAADZOS_BLUETOOTH_OK`, `KAADZOS_BLUETOOTH_MODULE_OK` and `KAADZOS_WAYBAR_OK` on live and installed boots and bounds its diagnostic probes with `timeout` (bluetoothctl otherwise waits for the daemon when no adapter lets Debian skip the unit), and `ci/test-desktop.sh` validates the Waybar JSON, the module wiring, the Sway binding, the helper/hook syntax and the probe bounds before the ISO build.
- Secure Boot: the base image ships `shim-signed` + `grub-efi-amd64-signed`, so the installed system's `grub-install` uses Debian's signed GRUB and shim; the live ISO's own GRUB is unsigned and boots with Secure Boot disabled.
- Releases are tag-driven and fully gated: pushing `v*` runs the whole matrix, and the `release` job (`if: startsWith(github.ref, 'refs/tags/v')`, `needs: [build, pack-test, repo-test, boot-test, install-test]`) re-runs `sha256sum --check` on the downloaded artifact before publishing `KaadzOS-trixie-amd64.iso`, `.sha256`, the signed `.sha256.asc` and the public key. Notes come from `docs/release-notes/<tag>.md` (fallback: generated notes). An existing release is refreshed with `gh release upload --clobber` + `gh release edit`, so re-running a tag refreshes the release safely, although a rebuilt ISO may not be byte-identical. A re-run uses the workflow file from the tag's commit, so jobs added later on `main` (such as `apt-repo`) require a new tag from current `main`; moving an existing release tag is not supported.
- Hosting is Cloudflare-only and credential-gated: Cloudflare Pages project `kaadzos` serves the website at https://kaadzos.pages.dev in the account selected by `CLOUDFLARE_ACCOUNT_ID`, and `.github/workflows/site.yml` deploys on `site/**` or `iso-site/**` pushes only when `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` secrets exist (otherwise it logs a notice and stays green). The site is a small React 19 + Vite build in `site/`: `npm ci && npm run build` produces `site/dist/`, which is what Pages deploys; the build runs even without Cloudflare credentials so a broken site fails CI. The editorial page remains hand-authored in `site/index.html` and `site/style.css`, with a self-hosted Inter Tight variable font (OFL, `site/public/fonts/`) and four vendored React Bits accents (`site/src/components/GradientASCII.*` at the top, `FlowingMenu.*` for the eight packs, `CursorGrid.*` behind the download chapter, `TechText.*` above the footer) mounted by `site/src/main.jsx`. The pack menu uses eight local colour images in `site/public/packs/` — seven Unsplash photographs and a Pixabay Android icon composited on white — and copies `kaadzos add <pack>` to the clipboard on click. All four mount points keep static fallback markup, so the page still reads without JavaScript. The Vite build has two HTML inputs: `site/index.html` and `site/docs/index.html`. `site/docs/` is a hand-authored manual that reuses the landing tokens, masthead and footer and adds a three-column docs layout with a sticky sidebar, on-page TOC, client-side search, scrollspy, heading anchors and copy buttons; `docs.css` and `docs.js` are local to that page and progressive-enhancement only. Both pages deploy together from `site/dist/` (`/docs/`). `site/public/_headers` sets `default-src 'none'`, `script-src 'self'`, `style-src 'self' 'unsafe-inline'` (the React accents set inline styles), `font-src 'self'` and images from self plus the CI screenshot host. The vendored React Bits files are MIT + Commons Clause, Copyright (c) 2026 David Haz; the full notice is in `site/src/components/LICENSE.md`.
- R2 public origin: the exact hostname https://iso.kaadzos.pages.dev is a Pages **preview branch alias** on branch `iso` of the `kaadzos` project, not a custom domain or nested DNS record. `site.yml` deploys `iso-site/` with `--branch iso`; `iso-site/_worker.js` runs in advanced mode, serves `/` from the static landing page and `/health` from the Worker, and streams every other path directly from the private R2 bucket through the project's `R2_BUCKET` binding. This avoids `r2.dev` rate limits and a domain purchase; the trade-offs are the Workers free-tier request budget (100,000/day) and streaming rather than edge-caching a 1.4 GB ISO (the CDN cache limit is 512 MB). The production `site/dist/` stays static and Worker-free, so https://kaadzos.pages.dev is unaffected.
- The release job also mirrors assets to Cloudflare R2 when `CLOUDFLARE_ACCOUNT_ID`, `R2_ACCESS_KEY_ID` and `R2_SECRET_ACCESS_KEY` are configured (bucket from `vars.R2_BUCKET || kaadzos`), writing `releases/<tag>/` through the S3-compatible endpoint; without them the step logs a notice and exits 0. R2 is enabled and the `kaadzos` bucket exists with Public Access disabled; all upload credentials are configured, and the v0.1.0 re-run (42366299998) mirrored the ISO under `releases/v0.1.0/` (1,432,977,408 bytes, range requests return 206). The bucket is exposed at https://iso.kaadzos.pages.dev by the `iso` Pages branch alias, and the `R2_PUBLIC_URL` variable is set to that origin.
- The optional APT archive is a signed deb822 repository built by `ci/build-apt-repo.sh` and published by the tag-only `apt-repo` job to Cloudflare R2 under `apt/`; `ci/test-apt-repo.sh` builds a throwaway signed repo with an ephemeral key and makes apt install from it in a trixie container on every build push. The first package is `kaadzos-pack-defs` (the canonical `packs/` tree at `/usr/share/kaadzos/packs`), built by `ci/build-pack-defs.sh`; its version matches the release tag. Publishing requires `CLOUDFLARE_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `APT_GPG_PRIVATE_KEY` and the `R2_PUBLIC_URL` variable, and skips cleanly without them. The same key signs the release checksum (`KaadzOS-trixie-amd64.iso.sha256.asc`). The ISO ships the keyring only when `APT_GPG_PRIVATE_KEY`, the R2 credentials and `R2_PUBLIC_URL` are present at build time; a generated chroot hook (after package installation) writes the source stanza only if the published `InRelease` is reachable, so the ISO build never queries an unpublished archive and the base image never depends on the optional one. The public archive origin is https://iso.kaadzos.pages.dev (the `iso` Pages branch alias), and the `R2_PUBLIC_URL` variable is set to it.
- CI scope: `build.yml` ignores `site/**`, `iso-site/**`, `.github/workflows/site.yml`, `docs/**` and `**/*.md` on branch pushes, because those paths cannot change the ISO; `site.yml` remains the only workflow for website and ISO-host changes. Tag pushes are never path-filtered, so a release still re-runs the complete matrix, and `workflow_dispatch` still forces a run.
