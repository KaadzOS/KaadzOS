KaadzOS 0.4.0 is the daily-driver release. The boot, installer, pack manager
and AMOLED look are unchanged from 0.3.0; this release fills in the missing
desktop services, the helpers around them, the optional packs that keep the
base ISO small, and the documentation needed to use and verify them.

## What changed

- Core baseline: the base list now names `7zip` instead of the `p7zip-full`
  transitional package, names `fdisk` explicitly, and keeps
  `--apt-recommends false`. `ci/test-base-list.sh` resolves the list in a
  trixie container in both `build` and `pack-test`.
- Portals and session integration: the base ships `xdg-desktop-portal`,
  `xdg-desktop-portal-gtk` and `xdg-desktop-portal-wlr`, with
  `/etc/xdg/xdg-desktop-portal/portals.conf` selecting GTK by default and WLR
  for screen cast and screenshot. The generated Sway config exports the
  private `dbus-run-session` bus and, with `--systemd`, the user manager;
  `kaadzos-session-ready` requires `KAADZOS_PORTAL_OK`.
- Bluetooth: BlueZ, Blueman and the explicit GLib/dconf packages are in the
  base. `bluetooth.service` is enabled but Debian skips it without an adapter;
  Waybar shows adapter, device and scan state, opens Blueman on left-click and
  toggles power on right-click. All `bluetoothctl` probes are bounded by
  `timeout`.
- Control centre: `kaadzos-control` sits behind the Waybar gear,
  `$mod+Shift+s` and a desktop entry. It probes every optional command and
  disables only the affected row. Base additions are `upower`,
  `power-profiles-daemon`, `wlsunset` and `zenity`.
- Settings: `kaadzos-settings` covers appearance, input, display, network,
  Bluetooth, sound, power, defaults and About. Wallpaper, keyboard and
  touchpad overrides are written atomically through `kaadzos-file-action`
  under `~/.config/sway/config.d/*.conf`, outside the generated config.
- Search: `$mod+d` runs `kaadzos-search`, a single TAB-separated fuzzel list
  of applications, recent and home files, settings pages, packs and fixed
  commands. It prunes sensitive directories and never evaluates a filename;
  `$mod+Shift+d` keeps the plain launcher.
- Package management: `kaadzos-packages` is the base front page behind
  `$mod+Shift+p`, the Waybar module, the desktop entry and Settings. Synaptic
  stays in the optional `admin` pack. Local `.deb` installs require an
  absolute path, warn about root maintainer scripts and log failures under
  `~/.cache/kaadzos/apt.log`.
- Helper and launcher validation: `ci/test-helpers.sh` runs dash syntax,
  shellcheck and all functional helper suites in both container jobs. The
  guest emits `KAADZOS_LAUNCHER_OK` only when helper binaries, desktop
  entries, launcher bindings and default MIME applications are all present;
  boot and install gates fail on `KAADZOS_LAUNCHER_MISSING`.
- OpenCode: the pinned, SHA-256-verified `v2.3.2` binary is available through
  the opt-in `opencode` pack with per-directory consent. It is not in the base
  image and adds no daemon, credentials, sudo rule or auto-start.
- New opt-in packs: `security` (`ufw`, `gufw`), `fonts` (Noto core, emoji and
  mono) and `input` (fcitx5, GTK/Qt frontends and Chinese addons) complete the
  pack matrix planned for printing, hardware, VPN, fonts and input methods.
- Daily-driver packs: `hardware` covers firmware, disk, SMART and sensor tools;
  `network` adds VPN plugins, WireGuard and NetworkManager tools; `printing`
  adds CUPS, drivers, scanning and mDNS discovery. All three are opt-in and run
  their hooks only on install.
- File actions: Thunar keeps its native menu and gains six safe actions — Open
  Terminal Here, Copy Path, Set as Wallpaper, Open as Administrator, Install
  Local Package and Open Settings — through `kaadzos-file-action`. Archive
  create/extract is provided by `thunar-archive-plugin` with `xarchiver`;
  `wl-clipboard`, gvfs/udisks2/thumbnail integration and `lxpolkit` round out
  the file manager.
- Documentation: `README.md` separates base features from optional and
  hardware-dependent features, records the no-dock decision and licence
  boundaries, and lists every pack. `site/docs/` now has 27 static chapters,
  including the new desktop, pack, security and OpenCode guides. Its search,
  scrollspy and copy buttons remain progressive enhancements.

There is no change to the release pipeline or the AMOLED artwork. No secrets,
non-free runtime dependencies or new base daemons were added.

## Download

- `KaadzOS-trixie-amd64.iso` (~1.4 GB, hybrid ISO)
- `KaadzOS-trixie-amd64.iso.sha256`
- `KaadzOS-trixie-amd64.iso.sha256.asc` (signed checksum)
- `kaadzos-archive-keyring.asc` (the archive/signing public key)

The ISO is mirrored at:

    https://iso.kaadzos.pages.dev/releases/v0.4.0/

Verify before writing to a USB stick:

    sha256sum --check KaadzOS-trixie-amd64.iso.sha256

To verify the signature as well, import the release key and check the checksum
file:

    curl -fsSL https://iso.kaadzos.pages.dev/releases/v0.4.0/kaadzos-archive-keyring.asc \
      | gpg --import
    gpg --verify KaadzOS-trixie-amd64.iso.sha256.asc KaadzOS-trixie-amd64.iso.sha256

The image is hybrid: the same file boots from a USB stick under BIOS or UEFI.
Secure Boot is supported on the installed system; the live image still requires
Secure Boot to be disabled.

## APT archive

The archive is served at:

    https://iso.kaadzos.pages.dev/apt

This ISO ships the keyring and the source stanza, so an installed system can
run `sudo apt update` immediately. The tag also publishes
`kaadzos-pack-defs` 0.4.0, the canonical pack definitions and hooks under
`/usr/share/kaadzos/packs`, including the new `security`, `fonts` and `input`
packs.

## Upgrades

This release is installed fresh. The APT archive delivers pack definitions, not
a new base image, so moving from 0.3.x to 0.4.0 means installing this ISO.

## How this build is verified

The release is published by CI only after the validation matrix for the tagged
commit is green. Every push builds the ISO and boots that exact ISO twice in
QEMU — once under Syslinux/BIOS and once under GRUB/OVMF UEFI. The boot test
waits for `KAADZOS_SWAY_READY` on the serial console (emitted only after a
successful `swaymsg` IPC query), requires the portal, helper, launcher,
Bluetooth and Waybar markers, fails if `swaynag` is running, and reports idle
RAM with the zram state. A third job drives the Calamares installer unattended
on a blank disk and boots the installed system, for both firmwares; it checks
that live sudo and Calamares are absent after installation.

The tag pipeline also runs `repo-test`, which builds a throwaway signed APT
repository with an ephemeral key and installs from it in a trixie container,
then publishes the real signed archive and the ISO assets. The release job
re-checks the SHA-256 before publishing.
