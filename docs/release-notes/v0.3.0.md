KaadzOS 0.3.0 is a visual release. The desktop, boot experience and
installer now use a true-black AMOLED palette with a white accent, matching
the website's black-and-white editorial design. The package set, pack manager,
installer flow and validation gates are unchanged from 0.2.1.

## What changed

- Replaced the blue-tinted Night palette with a true-black AMOLED one:
  `#000000` background, `#050505` bars, `#0a0a0a` surfaces, `#292929`
  hairlines, `#ffffff` primary text and accent, `#9c9c9c` / `#8a8a8a`
  secondary text, and a restrained `#ff5c5c` urgent state.
- Regenerated Sway, Waybar, foot, fuzzel, mako, swaylock, GTK3/4, Qt6ct, the
  console palette, the wallpaper, the Plymouth splash and the Calamares
  branding from `theme/palette`.
- Added GTK CSS overrides so Adwaita's blue selection and accent become
  white-on-black in GTK3 and GTK4/libadwaita applications.
- The installed system's greetd/tuigreet login now uses the same white/grey
  theme instead of the virtual console defaults.
- Rebuilt the boot-menu artwork and splash in black, white and grey, and
  reduced the wallpaper and installer glow so true black dominates.
- The Waybar Install button and active workspace are white, `os-release`
  reports a white ANSI colour, and the MOTD names the AMOLED palette.
- Replaced `KaadzNight.conf` with `KaadzAMOLED.conf` for Qt6ct.
- Replaced the Calamares progress page's QML slideshow with a native image
  panel. The install copy is baked into a pre-rendered AMOLED slide, so the
  first frame is black, the text cannot race the QML scene, and there is no
  white `QQuickWidget` placeholder.
- Added an `LD_PRELOAD` filter for Calamares' locale map. The embedded blue
  ocean, green timezone bands and red pin are converted to neutral greys when
  the module loads, while alpha is preserved for the timezone hit-testing, so
  the Location page matches the rest of the installer.
- Neutralized Calamares' hardcoded Breeze partition colours at build time:
  the blue/green/yellow/purple existing-partition palette, the red/orange
  new-partition palette and the purple-grey unknown-disklabel fill become
  neutral greys, so the Summary page's partition bars are monochrome too.

There are no package, pack or installer-flow changes. Re-download to get the
new look; the image does not include an in-place theme upgrade path.

## Download

- `KaadzOS-trixie-amd64.iso` (~1.4 GB, hybrid ISO)
- `KaadzOS-trixie-amd64.iso.sha256`
- `KaadzOS-trixie-amd64.iso.sha256.asc` (signed checksum)
- `kaadzos-archive-keyring.asc` (the archive/signing public key)

The ISO is mirrored at:

    https://iso.kaadzos.pages.dev/releases/v0.3.0/

Verify before writing to a USB stick:

    sha256sum --check KaadzOS-trixie-amd64.iso.sha256

To verify the signature as well, import the release key and check the checksum
file:

    curl -fsSL https://iso.kaadzos.pages.dev/releases/v0.3.0/kaadzos-archive-keyring.asc \
      | gpg --import
    gpg --verify KaadzOS-trixie-amd64.iso.sha256.asc KaadzOS-trixie-amd64.iso.sha256

The image is hybrid: the same file boots from a USB stick under BIOS or UEFI.
Secure Boot is supported on the installed system; the live image still requires
Secure Boot to be disabled.

## APT archive

The archive is served at:

    https://iso.kaadzos.pages.dev/apt

This ISO ships the keyring and the source stanza, so an installed system can
run `sudo apt update` immediately. The tag also publishes
`kaadzos-pack-defs` 0.3.0, the canonical pack definitions and hooks under
`/usr/share/kaadzos/packs`.

## How this build is verified

The release is published by CI only after the validation matrix for the tagged
commit is green. Every push builds the ISO and boots that exact ISO twice in
QEMU — once under Syslinux/BIOS and once under GRUB/OVMF UEFI. The boot test
waits for `KAADZOS_SWAY_READY` on the serial console (emitted only after a
successful `swaymsg` IPC query), dumps the framebuffer, fails the run if
`swaynag` is running, and reports idle RAM with the zram state. A third job
drives the Calamares installer unattended on a blank disk and boots the
installed system, for both firmwares.

The tag pipeline also runs `repo-test`, which builds a throwaway signed APT
repository with an ephemeral key and installs from it in a trixie container,
then publishes the real signed archive and the ISO assets. The release job
re-checks the SHA-256 before publishing.
