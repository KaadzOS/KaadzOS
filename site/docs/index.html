KaadzOS 0.3.0
Updated 16 November 2026

Overview

KaadzOS is a minimal Debian 13 (trixie) live image with a hand-built Sway/Wayland desktop, a pure-black AMOLED theme rendered from one palette, an on-demand pack system, and a Calamares installer. It boots on BIOS and UEFI, installs to disk, and is built and tested entirely in GitHub Actions.

Base

Debian 13 trixie, amd64

Session

Sway on Wayland, with Waybar, foot, fuzzel, mako and swaylock

Image

Hybrid ISO, about 1.4 GB, Syslinux BIOS + GRUB UEFI

Validation

Built, booted twice and installed twice before any release

Most of the design is forced by the environment, and that is the point.

No Hyprland
Hyprland is not in Debian stable, and the image builds from the archive with --apt-recommends false. Sway is in trixie, so Sway is the desktop.
POSIX sh
The pack manager is a shell script at /usr/local/bin/kaadzos. The base image ships no language runtime, and the CLI only orchestrates apt, dpkg, curl and systemctl.
CI-only
The ISO is not built on a development machine. Every push builds it, boots it under both firmwares, and drives an unattended install. A tag ships only what that matrix proved.
One palette
theme/palette is the single source of truth. Every themed surface is rendered from it, including the boot splash, installer and virtual console.
Opt-in weight
AI tooling, Android, Windows apps, gaming, creative suites and dev chains are declarative packs, not base-image payload.

What you need

KaadzOS runs on ordinary amd64 hardware and in QEMU. You do not need a build machine to install it.

ItemRequirement
CPUx86-64, with UEFI or legacy BIOS. AMD64 only.
MemoryThe CI live session idles at roughly 310 MiB with zram active. 1 GB is comfortable; packs want more.
USBA 2 GB or larger stick. The ISO is about 1.4 GB.
FirmwareSecure Boot disabled for the live USB. The installed system supports Secure Boot.
NetworkOptional for the live desktop. Required for packs, the APT archive and updates.
DiskA target disk or partition you can erase. The CI install test uses a 12 GB virtual disk.

Before you write

Writing the ISO to a USB stick erases it. Check the device name twice; /dev/sdX is a placeholder, not a suggestion.

Write the USB

The image is hybrid: the same file boots from a USB stick under BIOS or UEFI. On Windows, write it with Rufus or balenaEtcher in DD mode, not in ISO-copy mode.

Boot the live image

Insert the stick and select it in the firmware boot menu. The live session is read-only and runs entirely in RAM; nothing on the USB is modified.

  1. Pick the firmware entry. UEFI boots through GRUB, legacy BIOS through Syslinux. The menu waits 5 seconds on GRUB and 10 seconds on Syslinux before the default.
  2. Watch the splash. Plymouth shows the AMOLED KaadzOS mark, then hands the display to Sway.
  3. Land in the session. The live user is kaadzos, with passwordless sudo for pack installs. Waybar, a welcome terminal and a one-time installer notification appear. Sway has no desktop icons.

Live only

Changes in the live session live in RAM and disappear on reboot. Install to disk for persistence.

Network

NetworkManager is enabled and Waybar shows link state. If you booted straight into Sway, connect from a terminal with nmtui; the live image does not ship a graphical connection editor.

Install from the desktop

Use the white Install button in Waybar, press Super+I, or run kaadzos-install in a terminal. That wrapper preserves the Wayland environment and pins the Calamares configuration.

The desktop

Sway is a tiling Wayland compositor. The default session is deliberately small: a launcher, a bar, a terminal, notifications, a locker and a focused set of lean applications. Everything is driven from the Super key.

Waybar

The bar carries workspaces, the clock, network state, volume, and a white Install button. The button is hidden on an installed system. The bar is themed from the same palette as every other surface; there is no separate configuration to keep in sync.

Screenshots and recording

  • Print saves a full screenshot to ~/Pictures/Screenshot-*.png.
  • Shift+Print selects a region with slurp first.
  • Super+Print toggles screen recording with wf-recorder and writes ~/Videos/KaadzOS-*.mp4. Audio is off by default.

Memory and idle behaviour

zram-tools creates a zstd swap sized at half of RAM, paired with vm.swappiness=180 and vm.page-cluster=0. The boot test reports archive RAM and zram state on every CI run. swayidle locks the session after 600 seconds and before sleep.

Keyboard shortcuts

Super is the modifier. The bindings are generated into ~/.config/sway/config; editing that file directly is fine, but a theme regeneration will overwrite it.

Packs

The base image stays small. Heavy software is installed on demand from packs: plain key=value files that declare apt packages, an optional signed third-party repository, an optional hook, and the space they need. The pack manager is idempotent and only escalates when it has to.

Commands

How add and remove behave

  • State lives in /var/lib/kaadzos/installed, so repeating add or remove is safe.
  • add, remove and update escalate with sudo -E only when not root. list, status and addons never need root.
  • Requirements are checked before anything changes: wayland, binder, kvm, or a command in PATH.
  • --dry-run or KAADZOS_DRY_RUN=1 prints the plan without touching the system. KAADZOS_PACKS_DIR and KAADZOS_STATE_DIR support alternate roots for testing.
  • Packs are not a sandbox. apt installs system packages and hooks run as root.

The Add-ons menu

Super+A opens the same pack list in fuzzel. Selecting an available pack installs it in a terminal; selecting an installed pack removes it. The menu itself runs unprivileged and escalates only the chosen action.

Writing a pack

Packs are canonical in packs/<name>.pack. CI stages them into the image at /usr/share/kaadzos/packs; the staged copy is gitignored so the repository stays single-source. Hooks live in packs/hooks/<hook>.sh and receive add or remove.

KeyMeaning
nameRequired. Must match the filename without .pack.
descriptionRequired. One line for list and the Add-ons menu.
sizeHuman-readable installed size, for display only.
requiresSpace-separated checks: wayland, binder, kvm, or a command name.
aptPackages passed to apt-get install.
repo-urlOptional third-party apt repository; the key is imported and a signed-by source is written.
repo-suiteRepository suite. Defaults to trixie.
repo-componentsRepository components. Defaults to main.
repo-keyURL of the repository signing key, armored or binary.
hookOptional script name under packs/hooks/.

A pack must do at least one of apt, repo-url or hook; an empty pack is rejected. ci/test-packs.sh resolves every pack against trixie and exercises the CLI's dry-run, gating, idempotency and error paths on every build push, so a broken definition fails in about a minute instead of at the end of an ISO build.

Installing to disk

Calamares is included in the live image. It does not debootstrap a new system: it unpacks the live squashfs onto the target and repairs the copy in place. That keeps the installed system close to the exact image CI booted.

Launch it

  • the white Install button in Waybar, shown only in the live session;
  • Super+I;
  • kaadzos-install in a terminal;
  • the “Install KaadzOS” entry in fuzzel.

Do not run the raw binary

calamares refuses to run as the unprivileged live user, and sudo calamares skips the wrapper that supplies -c /etc/calamares and preserves the Wayland environment. Use kaadzos-install.

The flow

  1. Welcome and language. US English by default; the CI driver forces it so keyboard navigation is deterministic.
  2. Location. The locale map is filtered to neutral greys by kaadzos-calamares-map.so, preserving alpha for timezone hit-testing.
  3. Keyboard. US layout by default.
  4. Partitions. Choose the target disk. This erases it.
  5. User. The hostname is preset as kaadzos-<user>.
  6. Summary, then install. The partition bars are monochrome: a build hook rewrites Calamares' hardcoded Breeze colours to same-length greys. The progress page uses a pre-rendered AMOLED slide rather than a QML scene, so the first frame is black and the text cannot race rendering.

During the copy, Calamares unpacks the squashfs with unsquashfs and rsync, purges live-only packages before generating the initramfs, removes the live NOPASSWD sudo rule and CI configuration, writes the bootloader, and enables greetd for the installed system.

The installed system

It boots through greetd and tuigreet into the same Sway session. The Install button and the live sudo rule are gone. Secure Boot is supported through Debian's signed shim and GRUB; the live image itself remains unsigned and needs Secure Boot disabled. There is no in-place theme upgrade path between releases: moving from 0.2.x to 0.3.0 means installing the new image.

The CI test

The install test creates a 12 GB sparse disk, drives the pages with synthetic Sway clicks and wtype, powers off, then boots the installed disk without the ISO. It fails unless KAADZOS_MODE installed, KAADZOS_FIRSTBOOT_DONE, KAADZOS_LIVE_SUDOERS_ABSENT and KAADZOS_CALAMARES_ABSENT all appear, and the session has no swaynag warning.

APT archive

The optional signed archive lives at https://iso.kaadzos.pages.dev/apt for suite trixie, component main, architecture amd64. It carries kaadzos-pack-defs, the canonical pack definitions and hooks, so an installed system can receive new packs through apt upgrade instead of a new ISO. It is not a replacement for the Debian archive.

PathPurpose

Verify the archive

The archive is signed by the same key as the release checksum (fingerprint 7FC3 1B27 E931 570B 2D8C 3E42 9A4F 8D9E 9D5B 0C7A). Key rotation is trust-on-first-use: a system that already trusts the old key cannot bootstrap the new one automatically, so keep the old key available until the last image that shipped it is out of support.

To return to a stock Debian-only apt setup, remove /etc/apt/sources.list.d/kaadzos.sources and /usr/share/keyrings/kaadzos-archive-keyring.gpg.

The script writes Sway, Waybar, foot, fuzzel, mako, swaylock, GTK3/4, Qt6ct, the wallpaper, the virtual-console palette, the Plymouth splash and the Calamares branding. The boot-menu artwork and overrides are hand-authored from the same values. If Python and Pillow are available, the script also regenerates the raster artwork and the install slide; otherwise the committed PNGs are kept, so a machine without Python still builds a complete image.

Typography

The UI face is Inter Tight, the same variable family as this website. Debian's fonts-inter package ships Inter and InterDisplay but not Inter Tight, so the variable TTFs are vendored under config/includes.chroot/usr/share/fonts/truetype/kaadzos/ with their OFL licence, and KAADZ_FONT_UI="Inter Tight" is wired through every generated config. JetBrains Mono remains the terminal and code face, and DejaVu Sans is the fallback. The Calamares stylesheet names the family directly because the installer runs as root without the live user's font configuration.

Artwork

All OS artwork is flat: the wallpaper, the installer welcome and slide imagery, the boot-menu splash.svg and the Plymouth background are true black with hairline contour lines and waypoint dots only. There are no gradient washes or glows, and the generated GTK CSS flattens Adwaita's headerbar and button gradient overlays. The raster pieces are committed, so a build without Python still produces the complete, identical look.

Installer surfaces

Two Calamares surfaces are not palette-configurable and are neutralised explicitly. The locale map is converted to neutral greys at load time by kaadzos-calamares-map.so, with alpha preserved for timezone hit-testing. A build hook rewrites the hardcoded Breeze partition colours — the existing, new and unknown-disklabel fills — to same-length greys, and fails the build if Calamares ever changes those strings. A Calamares upgrade therefore cannot silently reintroduce a colour bar into the Summary or Location pages.

The website is a separate design system sharing the same black-and-white editorial language. The palette governs the OS surfaces, not the site.

Troubleshooting

Start with the checksum and the firmware entry. Most “broken image” reports turn out to be a truncated download, Secure Boot, or the wrong boot mode.

SymptomCheck
The USB does not appear in the boot menuVerify the SHA-256 first. Disable Secure Boot for the live USB and try the other firmware entry; the image is hybrid, so BIOS and UEFI both work.
The screen stays black after the boot menuWait for Plymouth; the live session can take a moment under emulation. Confirm the display is connected to the GPU that the firmware initialised, and try the other firmware mode.
No network in the live sessionNetworkManager is enabled. Run nmtui in a terminal and join the network there. Packs and updates need a connection; the base desktop does not.
kaadzos-install says the installer is live-onlyThat is expected on an installed system. On the live image, launch it from Waybar, Super+I, or the fuzzel entry.
calamares refuses to startDo not run the raw binary or sudo calamares. Use kaadzos-install, which supplies the config path and preserves the Wayland environment.
A pack needs a Wayland sessionRun the pack from the Sway session. The check fails over SSH or on a plain console because WAYLAND_DISPLAY is unset.
A pack needs binder or KVMThe kernel interface is missing. Enable the relevant module/device or nested virtualisation; the pack refuses to install without it.
apt update returns 404 or NO_PUBKEYThe tag's apt-repo job may not have published yet, or the keyring is missing at the path in Signed-By. Re-run the archive setup above.
Checksum mismatchRe-download the ISO. Do not write a file that failed verification.
swaynag shows a warning barThe Sway config emitted an error or a shadowed binding. CI fails on this deliberately; include the framebuffer screenshot and serial log in a bug report.
The build stops at “Qt6Gui development files are missing”Install g++ qt6-base-dev pkg-config before sh ci/build-map-filter.sh, or skip the filter and keep the stock locale map.
The build fails in 0510-calamares-amoledCalamares changed its hardcoded Breeze partition palette. Update the string map in config/hooks/live/0510-calamares-amoled.hook.chroot; the hook fails on purpose rather than shipping coloured partition bars.
The install test seems stuckUnder TCG a full unpackfs plus initramfs run is slow; the job allows 40 minutes. Synthetic clicks are used because the Alt+N mnemonic is unreliable when a combo box has focus.

Build the ISO

The canonical build is GitHub Actions, but the same live-build configuration runs locally in Docker or on a Debian trixie host. Budget about 10 GB of disk and five minutes of build time.

RequirementWhy
Docker (recommended) or Debian trixielive-build and its archive tooling.
~10 GB free diskThe chroot, squashfs and ISO.
g++, qt6-base-dev, pkg-configBuilds the Calamares locale-map filter. Optional, but the installer map stays blue/green without it.
Python 3 + PillowOnly to regenerate the committed wallpaper, logo and install slide artwork.

A local build without the APT signing secrets and R2 credentials skips the optional archive trust material. That is expected; the base image never depends on the archive.

Boot and install it locally

QEMU prefers KVM and falls back to TCG. The boot test drives the live menu, waits for the Sway IPC marker, dumps the framebuffer and fails if swaynag is running. The install test is the slower one: it copies the squashfs and boots the installed disk.

CI & releases

The validation matrix is the release policy. A tag does not ship an image that was built somewhere else; it re-runs the matrix for that exact commit and publishes only after every gate is green.

JobWhenWhat it proves
pack-testEvery pushEvery pack resolves against trixie; dry-run, requirement gating, idempotency and error paths work.
repo-testEvery pushA throwaway signed APT repository builds, apt installs from it, and gpgv rejects a tampered Release file.
buildEvery pushThe ISO builds from scratch and its SHA-256 file matches.
boot-test (bios)Every pushThe exact ISO boots to a working Sway session under Syslinux.
boot-test (uefi)Every pushThe exact ISO boots to a working Sway session under GRUB/OVMF.
install-test (bios)Every pushCalamares installs unattended and the installed disk boots without the ISO.
install-test (uefi)Every pushThe same, under UEFI, with the live-only state removed.
apt-repov* tagsBuilds and publishes the signed archive and kaadzos-pack-defs to R2.
releasev* tagsRe-verifies the checksum, signs it, publishes the release assets and mirrors them to R2.

The gates that matter

  • The boot test waits for KAADZOS_SWAY_READY, emitted only after a successful swaymsg IPC query, then dumps the framebuffer and publishes it to the ci-artifacts branches.
  • It fails if swaynag is running. A red warning bar means the Sway config emitted an error or a shadowed binding, so “it boots” is not enough.
  • The install test asserts KAADZOS_MODE installed, KAADZOS_FIRSTBOOT_DONE, KAADZOS_LIVE_SUDOERS_ABSENT and KAADZOS_CALAMARES_ABSENT, and applies the same swaynag gate to the installed session.
  • Idle RAM and zram state are reported as KAADZOS_IDLE_RAM on every boot run.

Cutting a release

  • Tag pushes are never path-filtered, so a release re-runs the whole matrix.
  • A re-run uses the workflow file from the tag's commit. Jobs added later on main need a new tag.
  • Release notes come from docs/release-notes/<tag>.md; a missing file falls back to generated notes.
  • Assets are published to GitHub Releases and mirrored under releases/<tag>/ on R2. Re-running a tag refreshes the release with --clobber.

Known limitations

  • No persistence in the live session; install to disk for a durable system.
  • The APT archive currently carries only kaadzos-pack-defs, not a replacement Debian archive.
  • The live image is unsigned and requires Secure Boot to be off. The installed system supports Secure Boot.
  • AMD64 only.
  • A full CI run takes roughly 30–50 minutes. The ISO build alone takes about five minutes and needs about 10 GB of disk.
  • iso.kaadzos.pages.dev is a Pages preview branch alias backed by a Worker that streams the private R2 bucket; the production site remains kaadzos.pages.dev.
